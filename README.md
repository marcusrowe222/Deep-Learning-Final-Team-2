### How the files are used

- **bigWig:** Provides the numerical target values the model learns to predict from DNA sequence.
- **BED:** Identifies accessible regions for exploring the data and evaluating predictions around peaks.
- **Reference genome:** Provides the matching GRCh38 DNA sequence used as the model's input.

### Data folder layout

The training and testing data loader uses these paths by default:

```text
data/
├── training/
│   ├── hg38.fa
│   ├── ENCFF667MDI.bigWig  (GM12878)
│   ├── ENCFF357GNC.bigWig  (K562)
│   ├── ENCFF770EAV.bigWig  (IMR-90)
│   └── ENCFF262URW.bigWig  (HepG2)
└── blacklist/
    ├── hg38.blacklist.rep.bed
    └── umap_k36_t10_l32_hg38.bed
```

Only the bigWig for the cell line being used is required. `hg38.fa.fai` is
the FASTA index, generated by pyfaidx; `hg38.fa.gz` is the compressed download
and is not needed after extracting `hg38.fa`. Peak BED files are not used by
the current training and testing data loader.

### Reference genome

[UCSC hg38 FASTA](https://hgdownload.soe.ucsc.edu/goldenPath/hg38/bigZips/initial/hg38.fa.gz). It contains the initial GRCh38 assembly and uses chromosome names such as `chr1`. The sequence is soft-masked: lowercase bases represent repeats, not missing DNA. See the [UCSC description](https://hgdownload.soe.ucsc.edu/goldenPath/hg38/bigZips/) for details.
- Uncompress the gzip file to process is with pyfaidx `gzip -dk hg38.fa.gz` -> outputs a `hg38.fa` file (same as .fasta file)

The authors' [training example](https://github.com/BoevaLab/ASAP/blob/main/tutorials/train.py) refers to an uncompressed `hg38.fa`. We need to check that chromosome names and lengths match the bigWig files.

### Training checkpoints

New training checkpoints store model weights, the cell line, the fold number, and the train, validation, and test chromosome lists. Testing checks the saved lists against the current data loader before evaluating.
